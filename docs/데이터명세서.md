# 데이터명세서

이 앱은 DB가 없고 파일(JSON/CSV/PDF/TXT)을 사용한다. 파일 구조를 "테이블"(TB)로, 필드를 "컬럼"으로 정의한다. 컬럼 참조는 `TB-01.contracts` 형식이다.
데이터 루트는 `data_roots()`가 정하며 EXE는 `%LOCALAPPDATA%\SaebomCompare`, 소스 실행은 프로젝트 폴더다.

## TB-01 catalog (목록 JSON)
파일: `downloads/catalog_expanded.json`. 작성: `load_catalog()`, 읽기: `read_catalog()`.

| 컬럼 | 설명 |
|------|------|
| mails | 메일 배열. 각 항목: id, from_name, from_email, to, subject, received_at, body, attachments |
| contracts | 계약 배열. 각 항목: id, kind, partner, partner_biz_no, title, service, period_start, period_end, amount_text, file |
| _synced_at | 마지막 목록 조회 시각 |
| _source | 조회 출처 |

## TB-02 files (저장된 원본)
폴더: `downloads/invoices`, `downloads/contracts`. 작성: `download()`, 위치 찾기: `cached_path()`.

| 컬럼 | 설명 |
|------|------|
| pdf | 원본 PDF. 이름은 `해시_종류_거래처_월.pdf` 형식 |
| txt | `read_pdf()`가 추출한 텍스트 (같은 이름, 확장자 txt) |

## TB-03 result (비교 결과)
`compare_mail()`이 반환하고 `save_reports()`가 `reports/<시각>/results.json`에 저장한다.

| 컬럼 | 설명 |
|------|------|
| mail_id | 메일 ID |
| subject | 메일 제목 |
| received_at | 받은 시각 |
| status | 일치 / 불일치 / 확인 필요 |
| checks | 항목 배열: item, status, detail, where |
| invoice_path | 세금계산서 PDF 경로 |
| contract_path | 계약서 PDF 경로 |
| contract_id | 연결된 계약 번호 |

## TB-04 where (비교값 위치)
`attach_locations()`가 `TB-03.checks`의 각 항목에 붙인다. 계산: `find_boxes()`.

| 컬럼 | 설명 |
|------|------|
| invoice | 세금계산서 박스 배열 |
| contract | 계약서 박스 배열 |
| page | 박스가 있는 쪽 번호 (1부터) |
| x, y, w, h | 페이지 너비·높이 대비 0~1 비율. 원점은 좌상단 |

## TB-05 reports (이력·보고서)
| 컬럼 | 설명 |
|------|------|
| history.json | 메일 ID별 최신 결과. `store_results()`가 갱신하고 `history()`가 읽는다 |
| results.json | 한 번의 비교 전체 (TB-03 배열) |
| results.csv | 항목별 행. UTF-8 BOM |

## 관계
TB-01 메일은 `TB-01.contracts`의 partner_biz_no로 계약과 연결되고, 연결된 PDF가 TB-02다. TB-02를 비교한 결과가 TB-03이며 TB-04는 TB-03의 항목에 포함된다. TB-03은 TB-05로 보관된다.
